# 微信通话录音（牛马保命神器）

在**未 root** 的安卓手机上自动录下微信语音通话，存成 wav。自用工具，APK 名「牛马保命神器」。

---

## 一、为什么普通录音录不到微信通话

安卓对"采集别人说话"这件事管得很死：

| 手段 | 能不能录微信通话 | 原因 |
|---|---|---|
| `CAPTURE_AUDIO_OUTPUT` | 不行 | 系统签名 / privileged 应用专用 |
| `AudioPlaybackCapture` | 不行 | 只能抓 `USAGE_MEDIA / GAME / UNKNOWN`；微信通话是 `USAGE_VOICE_COMMUNICATION`，被排除 |
| 普通 `AudioRecord`（MIC） | 不行 | 通话中麦克风被通话链路独占，读出来全是 0 |

所以"录音 App"在通话里基本是哑的。

## 二、这台机器上验证出来的两条活路

在 HUAWEI EBG-AN10（鸿蒙 4.2 / Android 12 / API 31 / 无 root）上逐项实测的结论：

**1. 音频源要选 `VOICE_RECOGNITION`**

| AudioSource | 通话中 |
|---|---|
| `VOICE_RECOGNITION` | ✅ 有数据，双方混音 |
| `MIC` / `VOICE_COMMUNICATION` / `CAMCORDER` / `UNPROCESSED` | ❌ 静音 |
| `VOICE_CALL` / `VOICE_DOWNLINK` / `VOICE_UPLINK` / `REMOTE_SUBMIX` | ❌ 直接被拒 |

用探针录下的样本做过音高比对，不是喇叭漏音，确实是通话双方的声音。

**2. 必须有「无障碍服务」身份**

同一个 `VOICE_RECOGNITION`，不带无障碍身份在通话中拿到的是静音。所以应用里挂了一个**空壳无障碍服务**（`MicA11y`）：不读屏幕内容、不做任何事，只为了让本进程在通话中拿到麦克风。

**3. 时序：麦克风必须在通话建立之后打开**

响铃阶段就建 `AudioRecord`，会拿到一个"之后被降级"的实例——通话接通后照样静音。因此触发的动作是**预热但不开麦**，确认接通后才创建 `AudioRecord`。代价是开头丢 0.2–0.5 秒。

## 三、怎么知道"通话来了"和"接通了"

两条信号，互相兜底：

| 信号 | 来源 | 特点 |
|---|---|---|
| 微信通知 | 通知使用权（`NotificationListenerService`） | 来电：`好友昵称邀请你语音通话`；通话中：`语音通话中`。快，但**时序不稳**（−5.4s ~ +0.8s 抖动） |
| 音频模式 | `AudioManager.getMode()` | 稳定，但**比接通晚约 2.7 秒** |

正常路径走通知：收到"邀请"→ 记录对方昵称、预热；收到"语音通话中"→ **只登记，等 `getMode()` 确认已接通才开麦**。

> 这一步是踩过坑的：早期版本收到"语音通话中"就立刻开麦，结果录出来只有自己、没有对方。
> 原因是该通知最多会比真正接通**早 5.4 秒**，在过渡状态里打开的 `AudioRecord` 会被路由到近端麦克风，
> 而不是通话混合通路。现在以 `getMode()` 为准（150 ms 轮询），通知只当提示；
> 模式 5 秒仍不上来才按通知兜底开麦，且开麦后 1 秒无信号会自动重开一次。通知文案被微信改掉时，退化为只看 `getMode()`：仍能录，但没有昵称、开头晚 2–3 秒。

## 四、落盘

- 录音线程按 **30 秒**切段，先写应用缓存（`CacheDir`），避免长通话占内存
- 挂断后把各段的数据区顺序拼接，重新生成一个 WAV 头，一次写成完整文件
- 目标目录：`Recordings/`（`MediaStore.Audio` 集合，Android 12 起系统认定的录音目录）
  - 写不进去时自动退到 `Download/通话录音/`
  - `MediaStore` 的集合与目录是强对应的：`Downloads` 集合只认 `Download/` 开头，塞 `Recordings` 会被拒
- 文件名：`call_<昵称>_<yyyyMMdd_HHmmss>_<XmYYs>.wav`
- 格式：16 kHz / 16 bit / 单声道

## 五、取流带来的影响

分两头说：对**正在进行的通话**，以及对**录下来的音质**。

### 5.1 对通话本身

- 本应用**只采集、不播放**，不存在自己录自己形成回授的问题
- 实测（本机、连续几天）：通话正常，没有卡顿、回声、对方听不清
- 但这是"没出事"的观察，**不是量化结论**——没测 MOS，没做丢包/延迟对比
- 已知风险：并行开两路采集时，个别机型的 HAL 会切音频处理链（关回声消除、降增益、改路由），可能出现回声或对方听感变差
- 如果真出现：把开麦时间再往后让 2–3 秒（用开头几秒换通话质量），或在设置里给出"录音期间不保证通话处理"的说明

### 5.2 对录音音质

| 约束 | 后果 |
|---|---|
| 固定 **16 kHz / 16 bit / 单声道** | 语音够用，音乐/环境声不行 |
| `VOICE_RECOGNITION` 是按语音识别优化的链路 | 自带 AGC + 降噪（可能还有带通），高频被削，有效带宽接近窄带电话 |
| 双方混在同一条轨 | 谁声音大就盖住谁，无分轨、无独立增益 |
| 提采样率到 48 kHz | **无收益**（推断，未实测）：源头带宽不够，重采样不会凭空补出高频 |

结论：**能听清、能回放、能当证据；不是高保真**。

### 5.3 为什么改不好

更高保真的两条路在免 root 下都走不通：

1. `CAPTURE_AUDIO_OUTPUT` 抓系统混音 → 需要系统签名 / privileged 权限
2. `AudioPlaybackCapture` 抓对方声音 → 微信通信用的是 `USAGE_VOICE_COMMUNICATION`，被采集策略明确排除

`VOICE_RECOGNITION` 是这台机器上**唯一还有数据**的通道，它的上限就是本应用的上限。

## 六、功能

- **自动录音开关**：三项权限（麦克风、通知使用权、无障碍）缺任意一项即点不动，点上去会说明缺什么并记一条日志
- **开机自启**：打开后重启手机自动把自动录音恢复起来（`BOOT_COMPLETED` 接收器；只在「开机自启」和「自动录音」都开着、且麦克风权限还在时才动手，否则记一条跳过原因）
- **权限自检**：界面上实时显示三项状态，缺项时提示"还差：无障碍，开关点不动"
- **自检 5 秒**：立刻开麦测 5 秒，报告 rms / 峰值 / 是否被静音，用来判断当前环境下这条通路通不通
- **文件列表**：二级页面，`Recordings/` 和老的 `Download/通话录音/` 都查，按时间倒序
- **半屏播放器**：
  - 上半是音频能量柱（按切片 RMS 生成），**点/拖直接 seek**
  - 参数区：时长、大小、采样格式、原文件名
  - 时间—进度—时间 + 六个控制键：`−1分 −15秒 ▶/❚❚ +15秒 +1分 ■`
  - 点播放器外的屏幕 → 收成迷你条 `▶ ▬▬●▬▬ 0:12`，播放不中断；点迷你条展开
- **跟随系统深浅色**：调色板放在 `res/values/colors.xml` 与 `res/values-night/colors.xml`，播放器、能量柱、迷你条都从主题取色，切到浅色不会再出现"深色播放器"
- **录音中实时电平**：通知栏每秒刷新 `电平 −31 dBFS ▮▮▮▯▯▯▯▯ · 峰 −7 · 3 段 · 静音=否`，
  一眼能看出这条通路到底有没有在收数据（全 0 时电平条是空的、dBFS 显示 −100）
- **事件日志**：界面上滚动显示，出问题时能看出走到哪一步

## 七、已知限制

- **单轨混音**：自己和对方在同一条轨上，无法分离
- **耳机 / 蓝牙未验证**：走耳机时 `VOICE_RECOGNITION` 可能拿不到对方声音
- **微信改文案即降级**：通知匹配靠中文文案，微信更新可能失效（退化为只靠音频模式）
- **长通话未压测**：30 秒切段 + 合并的设计上没有硬上限，但没跑过 10 分钟以上的实际通话
- **只有录音和播放**：没有删除、搜索、分享功能

## 八、代码结构

| 文件 | 职责 |
|---|---|
| `MainActivity` | 主界面：开关、权限检测、自检、事件日志 |
| `RecordService` | 前台服务，状态机 IDLE → PREHEAT → RECORDING |
| `Recorder` | `AudioRecord` 封装：打开、读、30 秒切段、静音检测、`selfTest()` |
| `NotifyListener` | 通知使用权：解析微信来电/通话中/挂断 |
| `MicA11y` | 空壳无障碍服务（不读屏幕、不记录任何数据） |
| `CallStore` | 分段合并成 wav、写 MediaStore |
| `RecordStore` | 录音文件查询（两个集合） |
| `PlayerSheet` | 半屏播放器 |
| `BarsView` | 能量柱绘制 + 触摸 seek |
| `AudioEnergy` | 流式扫描 wav 算 120 个切片的 RMS |
| `WavWriter` | WAV 头生成 |
| `EventLog` | 环形事件日志 |
